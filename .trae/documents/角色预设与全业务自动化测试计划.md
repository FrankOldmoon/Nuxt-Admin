# 角色预设 + 全业务自动化测试 + Phase 5 Agent 自动化 实施计划

## Context

用户要求「全部去做」，补齐 Phase 5 剩余项，并为 16 个角色预设所有业务权限，编写覆盖「所有角色 × 所有业务功能」的自动化测试。

当前事实（已核实）：

- `modules/sms/server/capabilities.ts` 已注册 61 个能力，每个能力声明 `permission`（`sms.<resource>.<action>`）。
- `capabilityPermissionMatches`（[capability.ts](file:///Users/oldmoon/Documents/github/Nuxt-Admin-SIS/server/core/capability.ts#L249-L270)）支持 `*` / `sms` / `sms:<action>` / `sms.<resource>` / 精确串。
- 角色种子（[seed.ts](file:///Users/oldmoon/Documents/github/Nuxt-Admin-SIS/server/database/seed.ts#L366-L379)）只创建 `admin` 与 `user`，且 roles 非空即整体跳过；实际只有 admin 可用新业务能力。
- `ModuleDefinition`（[moduleSdk.ts](file:///Users/oldmoon/Documents/github/Nuxt-Admin-SIS/server/core/moduleSdk.ts#L100-L108)）没有 seed 钩子，只有 `lifecycle` / `migrations` / `register`。
- [database.ts](file:///Users/oldmoon/Documents/github/Nuxt-Admin-SIS/server/plugins/database.ts) 中 `resolveModuleCatalog` 结果只在 dev 分支内可见；`seed(db)` 之后没有任何模块级 seed 调用。
- [nuxt.config.ts](file:///Users/oldmoon/Documents/github/Nuxt-Admin-SIS/nuxt.config.ts#L69-L75) 的 `nitro.experimental` 尚未启用 `tasks`，也没有 `scheduledTasks`。
- 考勤预警纯函数 `evaluateAttendanceAlerts` 已存在，但 `refreshAlerts` 是私有函数且只针对单个学生；缺少全库定时扫描。
- `canPublishScores` 与 `canPublishTimetable` 把数据范围标志 `.all` 当作发布权限，属于越权隐患。
- 迁移已到 `sms:011-assets-library`；`sms_attendance_alerts` 唯一索引为 `(organization_id, student_id, rule, window_start)`。

目标结果：

1. 16 个 `sms.<role_code>` 角色权限包可重复、幂等地写入数据库，不覆盖管理员自定义。
2. 每个角色的每条业务能力都有自动化断言（allow/deny 矩阵），且每个能力至少有一个业务角色可达。
3. Phase 5 定时考勤预警扫描与周报生成落地，并落库留痕。
4. 全量测试、lint、typecheck、build 通过；文档同步。

## 1. 角色权限预设

幂等规则：

- 按 `roles.name` 查找；缺失则 `insert`（`dataScope: 'all'`）。
- 已存在则 `permissions = mergeRolePermissions(existing, preset)`（并集、去重、保持顺序），**只增不减**，不覆盖管理员移除/自定义。
- 不修改 `admin` / `user`；`admin` 仍由 database 插件每轮重置为 `['*']`。

## 4. 角色 × 能力矩阵测试

新建 `modules/sms/test/roles.test.ts`（纯函数，不连数据库）：

- 用 `capabilityPermissionMatches(preset.permissions, capability.permission)` 计算可达性。
- 断言：
  1. 恰好 16 个预设，`name` 唯一且匹配 `/^sms\.[a-z_]+$/`；权限串合法（`*` 或 `/^sms(\.[a-z-]+){1,2}$/`）。
  2. `platform_admin` 对全部 61 个能力可达。
  3. 每个能力至少被一个非 `platform_admin` 角色可达（防止「只有超管能用」）。
  4. 每个预设的权限串都出现在 `smsModule.permissions` 中（防止拼写漂移）。
  5. 精确负向断言：
     - `sms.student` / `sms.guardian` 不能执行任何写能力（`sms.leave.apply` 除外）。
     - `sms.teacher` 不能 `sms.scores.publish` / `sms.timetable.publish`。
     - `sms.academic_staff` 不能发布成绩/课表，但能录入。
     - `sms.hr` 不能访问财务/成绩写；`sms.librarian` 不能访问资产；`sms.logistics` 不能访问图书。
     - 除 `platform_admin`/`sms.finance` 外无 `sms.finance.refund-approve`；退费审批与申请人分离由现有逻辑保证。
  6. `mergeRolePermissions` 单测：并集、去重、保留既有自定义权限。
  7. 高风险能力（`riskLevel === 'high'`）均有 `requiresApproval === true`（现有断言扩展到矩阵文件）。

## 5. Phase 5 Agent 自动化

### 5.1 数据表

[ schema.ts ] 新增 `smsReportRuns`（`sms_report_runs`）：

`id, organization_id, tenant_id, kind('weekly'), period_start, period_end, status('succeeded'|'failed'), payload jsonb, error text, generated_at`

[migrations.ts] 追加 `sms:012-report-runs`，DDL 全部 `IF NOT EXISTS`，索引 `(organization_id, kind, period_start)`。

[module.ts] `database` 增加 `'sms_report_runs'`。

### 5.2 任务逻辑 `modules/sms/server/jobs.ts`

- `weekRange(date): { start, end }`、`previousWeekRange(now): { start, end }`：UTC，周一~周日。
- `buildWeeklySummary(input, generatedAt)`：纯函数，输出 `period`、`metrics`（出勤、请假、成绩、财务）、`highlights`。
- `runAttendanceAlertScan(now = new Date())`：查近 90 天 `full_day` 记录，按 `(organizationId, studentId)` 分组，复用 `evaluateAttendanceAlerts`，批量 `insert ... onConflictDoNothing()` 写 `sms_attendance_alerts`；返回 `{ organizations, studentsScanned, alertsCreated }`。
- `runWeeklyReport(now = new Date())`：按组织聚合上周出勤/请假/考试/财务，写 `sms_report_runs`，返回运行记录；单组织失败写 `status='failed'` + `error`。

### 5.3 Nitro 任务与调度

- `server/tasks/sms/attendance-scan.ts`、`server/tasks/sms/weekly-report.ts`：`defineTask({ meta: { name: 'sms:attendance-scan' }, run: () => runAttendanceAlertScan() })`。
- [nuxt.config.ts](file:///Users/oldmoon/Documents/github/Nuxt-Admin-SIS/nuxt.config.ts#L69-L75)：`nitro.experimental.tasks = true`；`nitro.scheduledTasks`：

```ts
'0 1 * * *': ['sms:attendance-scan'],
'0 2 * * 1': ['sms:weekly-report']
```

### 5.4 测试 `modules/sms/test/jobs.test.ts`

- `weekRange` / `previousWeekRange` 边界（周一、周日、跨月、跨年）。
- `buildWeeklySummary` 指标与 highlights（无数据/有预警/待审批/欠费）。
- 不连数据库。

## 风险与边界

- 角色权限只增不减，避免覆盖管理员手工调整；如需回收权限需人工在后台移除。
- 定时任务依赖 Nitro `scheduledTasks`，serverless 部署需改为外部 Cron 调用任务路由，文档中注明。
- 测试矩阵只验证权限→能力可达性，数据范围（本班/本年级/子女）仍由现有 scope resolver 负责，不在本次新增数据库级测试。
